# PDF RAG System (Retrieval-Augmented Generation)

## Overview

This project implements a Retrieval-Augmented Generation (RAG) system for question answering over PDF documents.

Instead of relying solely on the internal knowledge of a language model, the system retrieves relevant information from documents and uses it to generate grounded and context-aware answers.

The system is designed with a modular architecture, separating ingestion, retrieval, processing, and generation components.

---

## Key Features

- PDF ingestion and preprocessing
- Semantic chunking
- Hybrid retrieval:
  - BM25 (keyword-based search)
  - Vector search (semantic search)
- Reranking using cross-encoder
- Query rewriting for improved retrieval
- Context filtering and construction
- LLM-based answer generation
- Simple evaluation pipeline

---

## System Architecture

User Query  
→ Query Rewriting  
→ Hybrid Retrieval (BM25 + Vector Search)  
→ Reranking  
→ Context Filtering  
→ Context Building  
→ LLM Generation  
→ Final Answer  

---

## How It Works

### 1. Ingestion
- Load PDF documents
- Split documents into chunks
- Clean and deduplicate chunks
- Generate embeddings
- Store in vector database

### 2. Retrieval
- Rewrite query for better retrieval (optional)
- Retrieve documents using:
  - BM25 (exact keyword matching)
  - Vector search (semantic similarity)

### 3. Reranking
- Use cross-encoder to rerank retrieved chunks
- Select top relevant documents

### 4. Context Processing
- Filter irrelevant chunks
- Build final context for LLM

### 5. Generation
- Generate answer using LLM
- Constrained to retrieved context

**Q3: How does the Transformer handle long-range dependencies?**

The Transformer handles long-range dependencies using multi-head self-attention, allowing each position in a sequence to attend to all other positions regardless of distance. This enables the model to capture relationships between distant elements effectively.
